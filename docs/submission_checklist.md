# Submission checklist

Source: guide pp.2,6-8,12. Section-5 penalties/bonus/tie-break rules are proposed pending organizer confirmation. All unchecked items are outstanding, not completed submission claims.

## Confirm at kickoff

- [ ] Record actual assignment, source/corpus rules and final organizer changes.
- [ ] Confirm prepared-code eligibility, submission platform/access, deadline timezone and exact before-15:00 cutoff.
- [ ] Confirm final bonus gate/rules, deck format/timing, `env.example` filename convention and API/network availability.

## Code and reproducibility

- [ ] GitHub link or compressed archive available. **Do not push without explicit permission**; a local archive satisfies the preparation route.
- [ ] Include README with installation, run command, architecture, actual limitations and AI disclosure.
- [ ] Include tested requirements/lock and Python version; explain CPU-only dependency source and model first-download/cache instructions.
- [ ] Include credential-free `.env.example`; include an equivalent `env.example` if organizer expects the literal guide filename.
- [ ] Include small licensed or explicitly synthetic sample data and steps that work without team assistance.
- [ ] Keep ingestion/retrieval/generation/UI modules clear; meaningful tests pass in intended environment.
- [ ] Review source/licenses/AI ledger; attribute reused code/project/materials.
- [ ] Inspect archive and any Git history for keys, `.env`, private uploads, personal chats/logs and sensitive data.
- [ ] Exclude `.venv`, caches, large model weights and indexes unless explicitly required/permitted; preserve access/rebuild instructions. Do not accidentally exclude necessary small sample fixtures or reviewed eval evidence.
- [ ] Extract archive elsewhere and follow README; record actual startup/test outcome.

## Evidence and product

- [ ] At least 10 real corpus-grounded questions with reference answers and relevant-source labels.
- [ ] Actual retrieval metrics, reviewed faithfulness, latency, case outputs, errors, failure/improvement analysis and exact config.
- [ ] Working cited answer; page/source can be opened; unsupported/OOS question refuses.
- [ ] Three unseen-style questions can be entered directly; no hardcoded answers.
- [ ] Arabic RTL product runs locally before judges or via working link; actual retrieval behind UI.
- [ ] Optional feature (history/upload/etc.) works safely if claimed; otherwise omit claim.
- [ ] Bonus conditional on technical score >=15/30; no self-awarded bonus reported as judge result.

## Deck and optional video

- [ ] PDF or PPTX, at most 12 slides, final export opens and fonts/RTL are correct.
- [ ] Problem/affected users/statistic; RAG architecture; demo/examples with sources.
- [ ] Sourced TAM/SAM/SOM; pricing/payer/unit economics; costs, 12-36-month forecast and break-even.
- [ ] Marketing audience/channels/budget/KPIs/90 days; alternatives/differentiation; team roles and next steps.
- [ ] Every factual business figure has source/context; every estimate visibly labeled an assumption.
- [ ] Five-minute rehearsal passes; Q&A ownership assigned; final ask clear.
- [ ] Optional video, if submitted, is 2-3 minutes, real running system; prefer 3 questions including citation and refusal; playback verified.
- [ ] Backup authentic demo recording/screenshots available if live generation/network fails.

## Deadline and final handoff

- [ ] Final archive/deck/video filenames and contents frozen with time to spare.
- [ ] Submit **before 15:00**; target 14:50 or earlier (team buffer proposal).
- [ ] Verify recipient/platform can access files/link; retain receipt and exact submitted artifact/hash.
- [ ] Keep system running for 15:00-16:30 judging availability; guide prefers sessions end by 16:15.
- [ ] Proposed lateness penalty is 2 points/5 minutes, max 10; do not rely on a grace period or unspecified rounding.

No submission destination or file-size limit is specified in the PDF. Do not invent one.
