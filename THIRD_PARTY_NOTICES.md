## Dependency compatibility review - November 7, 2026

**Unresolved blocker: `regex==2026.9.29`.** Its installed metadata and [upstream release page](https://pypi.org/project/regex/2026.9.29/) declare `Apache-2.0 AND CNRI-Python`, not a choice between the two. The installed license says its original code uses CNRI's Python 1.6 license; Apache 2.0 applies to additions/alterations. Transformers 4.57.1 requires `regex`, so this is an actual transitive dependency, not an unused package that can simply be ignored.

[SPDX identifies CNRI-Python](https://spdx.org/licenses/CNRI-Python.html) as the original Python 1.6b1 license. [Python's official copyright page](https://www.python.org/doc/copyright/) describes the original 1.6b1/1.6 license as GPL-incompatible because of its choice-of-law clause. This creates an unresolved concern for combining the pinned runtime with AGPL code. This review does not assert that merely listing the dependency is unlawful or give a definitive legal conclusion about this application; it cannot certify the required overall compatibility. The repository has therefore **not been committed or pushed** under the owner's conditional authorization.

Do not silently relabel `AND` as `OR`, substitute the modern PSF license for the declared CNRI license, remove the dependency, or change versions without review/testing. Resolve the exact release's provenance/permission with authoritative upstream clarification or appropriate licensing review; alternatively obtain approval for a demonstrated compatible dependency change and regression checks. No such change or contact was performed.

Other findings, scoped to this source-only selection (not a redistribution of the installed runtime):

- Most distributions declare MIT, two/three-clause BSD, Apache-2.0 or PSF-family terms. [GNU's compatibility discussion](https://www.gnu.org/licenses/license-compatibility.en.html) and [Apache's GPL compatibility page](https://www.apache.org/licenses/GPL-compatibility.html) support the version-3 compatibility route for Apache-2.0; notices and other upstream conditions still apply.
- Missing short metadata was resolved: Colorama 0.4.6 and Jinja2 3.1.6 have installed BSD-style license files; Safetensors 0.8.0 has an installed Apache-2.0 license; [Tokenizers v0.22.2](https://github.com/huggingface/tokenizers/blob/v0.22.2/LICENSE) has the upstream Apache-2.0 license. None is treated as unlicensed simply because a metadata field was empty.
- Certifi declares MPL-2.0; tqdm declares MPL-2.0 and MIT. Preserve their component notices and MPL source obligations if redistributing them. [Mozilla's FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/) explains the conditions for combining eligible MPL code with GNU-family licensed works; do not assume all MPL variants are interchangeable.
- Pywin32's package metadata says PSF, but installed bundled notices also include LGPL-2.1 and other component terms. NumPy, SciPy, Pillow and PyTorch likewise carry bundled-component notices beyond a single top-level label. Those binaries/components are not included in this repository. Any later bundled executable, container, wheel/cache transfer or deployment needs its own corresponding-source/notice review; the current project license does not erase those terms.
- Font embedding was checked separately. Both existing OFL notices and both synthetic PDFs are preserved unchanged. No official organizer document, model weights or third-party library source/binary was added.

No other concrete conflict was identified in this review, but no blanket clearance of all future distributions/deployments is claimed. The `regex` concern remains unresolved and prevents this publication attempt.
